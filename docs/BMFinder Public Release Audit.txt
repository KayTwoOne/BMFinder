----- page 1 -----
You are working on the public release of BMFinder, a Chromium Manifest V3 browser extension for
Brave, Chrome, and Edge.
Your task is to audit and refine the public build so its language, information architecture, defaults,
privacy disclosures, exports, and deletion controls accurately communicate its primary purpose:
BMFinder helps Arma 3 players save, recognise, and reconnect with friends, teammates,
and familiar community members through BattleMetrics information already visible to
the user.
This is an implementation task, not merely a design proposal. Inspect the existing repository,
understand the current architecture and state flow, make the changes described below, update tests
and documentation, and report exactly what changed.
Do not rewrite the extension from scratch. Preserve reliable existing functionality, the Material 3 token
system, current theme support, IndexedDB architecture, extraction centralisation, and the existing
deliberate pacing of page navigation.
1. Product context
Arma 3 players frequently change their in-game names. The game does not provide a convenient way
to connect an in-game identity with a Steam friend identity. Adding someone on Steam normally
requires both people to exchange an exact name or profile link, which can be mistyped or difficult to
find.
BMFinder exists primarily to let a user:
Save friends and familiar players.
Give them a persistent personal label.
Recognise them after they change their in-game name.
See whether they are currently playing.
See which followed server they were last observed on.
Find other familiar people they may want to join.
Maintain a short, private, local history.
Transfer a deliberately selected list to a trusted friend where appropriate.
BMFinder is not intended to operate as:
A public player-intelligence database.
A stalking or harassment tool.
A method for bypassing private BattleMetrics profiles.
An automated accusation or enforcement system.
A commercial player-data product.
A way to infer a hidden person’s identity from missing roster entries.

2.1 Features that must not exist in the public build
The public build must not contain, expose, register, route to, or silently retain:
Incremental player-ID range scanning.
Any control that walks consecutive player IDs.
Absence correlation.
Admin-versus-player presence correlation.
Suspicion scoring.
Behavioural risk scoring.
Automatic recommendations to investigate, punish, flag, or ban a player.
A “Suspect” relationship role.
UI language that claims an unavailable player is a hidden administrator.
Logic that attempts alternative endpoints specifically to reveal a profile after BattleMetrics
returns it as private, unavailable, 404, or not found.
Search the complete public build—not only visible components—for old routes, handlers, strings,
storage keys, commands, tests, feature flags, CSS, documentation, and dead imports related to these
capabilities.
Remove them from the compiled public extension rather than merely hiding buttons with CSS.
Do not remove anything from a clearly separate private development branch or private edition unless
the repository structure requires separation to prevent it being bundled publicly. Where necessary,
create a clean build-time boundary so the public package cannot accidentally include the excluded
code.
2.2 Privacy controls must be respected
BattleMetrics may return a profile as private, unavailable, deleted, inaccessible, or not found.
When this occurs:
Stop the lookup normally.
Do not try to infer the player’s identity.
Do not label the player as an administrator.
Do not claim the user has deliberately hidden themselves.
Do not imply wrongdoing.
Do not attempt alternate routes intended to defeat the unavailable state.
Do not expose raw error details that encourage circumvention.
Use neutral copy:
Title: “Profile unavailable”
Body:
“BattleMetrics is not making this profile available to your current session. It may be private, deleted,
temporarily unavailable, or inaccessible with your current permissions.”

BMFinder
BMFinder is a local browser extension that helps Arma 3 players save and recognise
friends, teammates, and familiar community members through BattleMetrics.
Players often change their in-game names, and Arma 3 does not provide a simple way to
connect an in-game identity with a Steam friend. BMFinder lets you keep your own labels,
follow familiar players and servers, and check whether anyone you know is playing.
BMFinder stores its working data in your browser profile. It does not operate a central
player database and does not attempt to reveal profiles that BattleMetrics makes private
or unavailable.
Retain useful technical explanations, but revise or remove passages that make the public extension
sound like an anti-bot workaround, hidden-admin finder, scanner, or investigative tool.
It is acceptable to explain honestly that the extension reads rendered pages instead of reproducing
private request-signing logic. Phrase this as a technical boundary, not an achievement in defeating
protections.
Move detailed historical experiments involving API failures and Cloudflare challenges into a
development-history document if they are not necessary for ordinary installation or use.
Ensure the public README accurately states that:
ID-range scanning is not included.
Absence correlation is not included.
Private and unavailable profiles are respected.
Data is local unless deliberately exported.
Observations are incomplete and are not proof.
Live updates are deliberately paced.
The project is independent and not endorsed by BattleMetrics.
16. Acceptance criteria
The work is complete only when all of the following are true:
The visible public interface contains no “Suspect” role or accusatory defaults.
The public build contains no ID-range scanner.
The public build contains no absence-correlation engine or UI.
Private or unavailable profiles receive a neutral, non-inferential state.

Per-player, per-server, recent-history, and delete-all controls exist.
