# Two builds, one source

`extension/` is the only place you edit. Everything else is generated or copied
from it.

| Directory | What it is | How it gets there |
| --- | --- | --- |
| `extension/` | The full version. Source of truth. | You edit it. |
| `commit/` | Full version, for the private GitHub repo. | Copy of `extension/`, plus a `.gitignore`. |
| `webstore/` | Reduced version for the Chrome Web Store. | Generated by `build-webstore.mjs`. Never edit by hand. |
| `webstore-assets/` | Store paperwork (privacy policy, listing copy, permission justifications, data disclosure). | Written once, updated when the feature set changes. |

## Building the webstore version

```bash
node build-webstore.mjs
```

It wipes and regenerates `webstore/`, then verifies its own output. If any check
fails it exits non-zero and tells you not to publish. The build is safe to run
as often as you like.

## What the webstore build removes

- Sequential player-ID enumeration (the ID Scan tab) and date-bisection probing
- The absence-correlation engine, plus `lib/correlation.js` and its tests
- Polling intervals below 5 minutes. 5 minutes becomes both the floor and the
  default, in the picker, in the dashboard clamp and in the worker's alarm
- `bookmarks` moves from a required permission to an optional one, requested
  when the user clicks the import button rather than at install

Removed means **absent from the package**, not disabled by a flag. A reviewer
reads what ships, so code that is present but unreachable is still present.

## How the stripping works

Regions are marked in the source, so the boundaries are decided by whoever edits
the code rather than guessed at by a script:

```js
/* @full-only */              // strip this one line
/* @full-only:start */        // strip everything through the matching end
/* @full-only:end */
```

HTML uses `<!-- -->` comments with the same words. Start and end may share a line
for a single element.

**Put a marker on its own line, never inside another block comment.** A marker
placed in the middle of a `/* ... */` splits that comment: the opening `/*`
survives the strip and the file stops parsing. The build catches this now (it
runs `node --check` on every emitted file), but the failure is avoidable.

## What the build checks before it will pass

1. No enumeration, correlation or leftover marker text anywhere in the output
2. Every emitted `.js` file still parses, via `node --check`
3. Feature-only files are actually gone
4. The manifest parses, is v3, and has `bookmarks` optional rather than required
5. No polling interval below 5 minutes in the `#mon-interval` picker
6. 5 minutes is the selected default
7. The dashboard clamps at the 5 minute floor
8. Every element id the JS dereferences exists in the HTML
9. No duplicate element ids
10. Every message the dashboard sends has a matching worker handler

Checks 8 and 10 exist because the risk of stripping is removing markup while
leaving the handler that reaches for it, which throws on load and takes the
whole page down.

## After building

```bash
cd webstore && npm test     # 19 tests
cd extension && npm test    # 25 tests, the 6 extra are correlation
```

Then load `webstore/` unpacked in Chrome and click through Search, Watchlist,
Servers, Monitor and Archive before packing it.

## Before submitting to the store

- Fill in `[CONTACT EMAIL]` in `webstore-assets/PRIVACY.md`
- Host the privacy policy at a public URL and put that URL in the listing
- Confirm the category name in `webstore-assets/STORE-LISTING.md` against the
  live developer dashboard
- Replace `icons/search.png` with real 16, 32, 48 and 128 pixel icons. It is
  currently one 512px file referenced at all four sizes, which Chrome will
  downscale into a muddy toolbar icon
- Take listing screenshots at 1280x800 or 640x400
