# One source, one package

`extension/` is the only place you edit. `webstore/` is generated from it.

| Directory | What it is | How it gets there |
| --- | --- | --- |
| `extension/` | The extension. Source of truth. | You edit it. |
| `webstore/` | What you upload to the Chrome Web Store. | Generated by `package-webstore.mjs`. Never edit by hand; it is git-ignored and rebuilt on demand. |
| `webstore-assets/` | Store paperwork: listing copy, permission justifications, data disclosure, store icon, screenshots. | Written by hand, updated when the feature set changes. Not part of the upload zip. |

## Building the package

```bash
npm run package
```

It wipes and regenerates `webstore/`, then verifies its own output. If any check
fails it exits non-zero and tells you not to publish. Safe to run as often as
you like.

> **This used to be a 343-line transformer.** The public build was once a
> reduced version of a larger private one, stripped at `@full-only` markers. That
> distinction is gone: ID enumeration and absence correlation were deleted from
> the source outright rather than stripped from one copy, and the manifest and
> polling floor the public build wanted are simply what the source now says. A
> transformer that transforms nothing is a place for bugs to hide, so it was
> replaced with an honest copy-and-prove.

## What the package leaves out

Only files a browser has no use for:

- `test/` &mdash; the Node test suites
- `package.json` &mdash; dev tooling manifest, not the extension manifest
- `README.md` &mdash; developer documentation

Everything else is copied byte for byte and then proven identical.

## What the packager checks before it will pass

1. All 35 files are byte-identical to their source in `extension/`
2. The package contains exactly the shipping files, and nothing else
3. No test or tooling files made it in
4. The manifest parses, is v3, and declares the expected permissions
5. `bookmarks` is optional rather than required
6. Every file the manifest references actually exists
7. Every permission, including the host permission, has a written justification
   in `webstore-assets/PERMISSION-JUSTIFICATIONS.md`
8. The store listing quotes the manifest description exactly

Check 8 exists because the listing and the manifest drift easily, and a
mismatch between them is a question a reviewer will ask.

Separately, `npm run verify` runs the source-level checks: duplicate element
ids, JS reaching for markup that no longer exists, retired vocabulary in
user-visible text, consent gating, and that every URL in the source points at
battlemetrics.com.

## After building

```bash
npm test        # 74 tests, run from the repository root
npm run verify  # static checks: duplicate ids, dead refs, retired vocabulary
npm run check   # both of the above, then a package build
```

Run these from the root. `webstore/` has no `package.json` of its own &mdash; the
packager deliberately leaves it out &mdash; so there is nothing to run in there.

Then load `webstore/` unpacked in Chrome and click through Find players,
People, Servers, Live activity, Recent activity and Data and privacy before
packing it.
