ID range scan

Walk a block of player IDs one at a time, matching each name against a target. Every ID costs a full page load in a real tab, so keep the range small.

Pick where to start before you scan

A linear walk covers a few hundred IDs an hour against a space of hundreds of millions, so where the range starts matters far more than how long it runs. Seek a date first: that bisects the ID space in about thirty page loads and hands back a neighbourhood worth scanning.

Why bisecting works

IDs are handed out in roughly the order BattleMetrics first sees each player, and every player page reports its first-seen date. That makes the ID space an approximately sorted array keyed by date, so each probe can discard half of what is left. It is approximate, not exact, so the seek reports the bracket it actually probed rather than a single boundary it cannot prove.

Seek an ID by date

Finds roughly where accounts first seen on a given date sit in the ID space, then offers that as the scan start.

Player IDs are global and roughly chronological, now in the hundreds of millions. Seed the start near a known contemporary rather than starting at 1.

Observation-based results

BMFinder records only the activity it observes while monitoring is running. Correlations are investigative leads, not definitive matches.

Why the numbers need time

Correlation built from occasional short runs samples your own habits as much as anyone else's: a player looks “absent whenever an admin is on” if you only ever polled while they happened to be offline. Long uninterrupted runs are what make the ratios mean something. Treat a high percentage as a lead worth checking, never as a verdict.

Polling

Each cycle loads every tracked server once and stores who was on it. The schedule is kept by the extension, so it survives closing this tab and restarting the browser. Pause stops scheduling new cycles and lets any cycle in flight finish. Stop also cancels the cycle in flight. Neither deletes anything.
